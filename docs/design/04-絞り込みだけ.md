# 04 照合しないで「絞り込みだけ」（進め方 §3〜§9・§13）

作成：2026-10-27

## 1. 要求整理（進め方 §3）

依頼：「照合せずに絞り込んだ結果だけを表示させる機能も欲しい。現状だと照合が必須のため使いづらい」

現状：① を読み込んで見出しから絞り込むと ① タブには絞り込み後の行が出るが、右上の主要動作は「② 照合表を読み込む」→「条件を追加する」と照合へ誘導し、出力は抽出結果タブからしかできない。ピボット・グラフだけは ② なしで ① の全行（絞り込み後）から作れる。

依頼者と合意した前提（Q1〜Q5 はすべて提案どおり）：

| # | 決定 |
|---|---|
| 1 | 結果は前処理すべて（縦に結合 → 縦持ち → 列の追加 → 絞り込み → 重複の削除）を掛けた ① の行 |
| 2 | 入口は作業セットごとの切替（照合して抽出／絞り込みだけ）。条件 0 件で自動に切り替える方式は誤認につながるため採らない |
| 3 | 絞り込みは照合するときと同じ ① の絞り込みを共有し、切り替えても残す。結果の見出しから絞るとその場で反映 |
| 4 | 絞り込みだけでも前回との比較を使える。判定の根拠は簡易表示。出力の記録に「照合なし」を残す |
| 5 | 照合と絞り込みだけを 1 つの作業セットで混ぜるのは対象外（残件 `separate`） |

主な作業の流れ：① を読み込む（差し替える）→ 見出しの一覧で絞り込む → 確かめる → 出力する。
例外状態：絞り込み後 0 件、絞り込みなし（全行）、処理中、切り替えた直後（元に戻す）。

- 利点：照合するかしないかが、作業セットという今ある仕事の単位に保存される。毎月の繰り返しで判断がいらない。主要動作は 1 つのまま、どの画面でも今の流れを文字で再認できる。抽出結果タブを使うので、比較・根拠・記録・ピボット・グラフの置き場所を新しく作らずに済む。
- 減点：入口が 4 か所で言葉がばらばら／最初の画面で全員に判断を増やす／「照合せずに…出力する」というボタンが実際には切り替えるだけ／照合に戻すスイッチが休止中のパネルの中／切り替えに「元に戻す」がない／行数が要約と処理の流れの帯に二重に出る／0 件・全行の状態が未設計。

## 6. 切替を上部バーへ移す（依頼者の指摘・§13.2 の中規模な修正）

依頼者の指摘：「絞り込みへの切り替えを左のパネルの抽出条件で行っているので認知負荷が高い」「絞り込みだけではピボットやグラフは使えない？」

- 原因：照合するかどうかは、抽出条件を作る前の「作業のしかた」の判断なのに、常に見える切替が抽出条件パネルの中にしかなかった（作業の順と画面の並びのずれ）。一度照合して結果が出たあとは、パネルを開かないと切り替えられなかった。
- 依頼者の決定：切替は**上部バーの作業セット名の右**（作業セットごとの設定のため、近接で「このセットの設定」と分かる。どのタブ・パネルでも同じ位置）に置き、**入口はそこ 1 か所**にまとめる（抽出条件パネルの先頭・結果の要約の「照合して抽出に戻す」・「あと少し」の画面のボタンは外し、案内の文だけ残す。Ctrl+K は補助の入口）。
- ピボット・グラフ：絞り込みだけでも絞り込み後の行で使えていたが、ピボットタブの主要動作が「○ 行を出力する」のままだった（出力はピボットの表なのにラベルが食い違う不具合）。「ピボット（○ 行）を出力する」に直した。

## 7. 見出しの一覧で外した値を戻せるようにする（依頼者の指摘・§13.2）

依頼者の指摘：「フィルターを掛けると外されたものがタグ表示となり、フィルターでは元に戻せない。認知負荷が高い」

- 原因：抽出結果の見出しの一覧は「今の結果に出ている値」だけで作っていたため、外した値が一覧から消えて、チェックを入れ直せなかった。タグも「地域：福岡・札幌 以外」と外した値で書いており、残っている値を逆算させていた（① タブのタグは残す値で書くので食い違っていた）。
- 依頼者の決定（すべて推奨どおり）：① 外した値はチェックなしで一覧に残す（Excel のオートフィルターと同じ。件数はほかの列の絞り込みを掛けた行）② タグは残している値で書く ③ 照合するときの抽出結果の ① の列も同じにする（① タブの一覧と同じ中身）。
- 実装：`LQ.ColumnMenu._prepare`（一覧の中身を 1 か所で作る。① タブ・抽出結果の ① の列で共通）／保存は「残す値」。ほかの列の絞り込みで一覧に出ない残す値は持ち越す。直した絞り込みはタグの同じ位置。以前の「除く値」も表示は残す値に直す（`RowFilter.describe(f, isDate, ds)`）。

再評価（評価役。変えた画面だけ）：認知コスト 18・ユーザビリティ 18・情報設計 16・作業フロー 17・一貫性 17 ＝ **86**。§9 の重大問題はなし。

| # | 指摘 | 対応 |
|---|---|---|
| 1 | 照合するとき、一覧の件数が ① の行数で、結果の行数と合わない | 一覧の上に「件数は ① 元データの行数です（ほかの列の絞り込みの後・照合の前）」を添えた（絞り込みだけでは結果と一致するので出さない） |
| 2 | 抽出結果の見出しの一覧で、② の列だけが前の動き | 依頼者に確認中（03 残件の 19） |
| 3 | 見込みの文が開いた場所で違う | ① タブと同じ「2,000 行 → 167 行になります（ほかの列の絞り込み 1 件も含む）」にそろえた |
| 4 | 残す値が多いとタグが「ほか 2」で省略される | タグにマウスを乗せると、残す値をすべて出す |
| 5 | 結果の見出しで外した値の保存が「除く値」→「残す値」に変わる（次の月の新しい値は外れ、通知される） | accepted（03 残件の 20） |
| 6 | ほかの絞り込みで一覧に出ない残す値はタグには出る | accepted（値を黙って失わないための意図した動き。03 残件の 21） |

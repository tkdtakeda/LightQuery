# レイアウト 5 案（静的モック）

進め方 §4 に従い、画面全体のレイアウトを異なる仮説で 5 案作ったものです。本処理にはつないでいません。
各ファイルを Edge で直接開き、下の帯の「モックの状態」で 初期・結果・条件の編集・抽出中・更新なし・履歴 を切り替えて見られます（`?shot=1` で帯を隠す）。

色・文字・表・データ・表示密度の部品は `mock-common.css` / `mock-common.js` で 5 案共通にし、違いを「配置と流れ」だけにしています。

| 案 | ファイル | 仮説（この構成で何を減らそうとしているか） |
|---|---|---|
| A 作業順レール | `plan-a.html` | 今の構造（作業順のアイコン列＋脇パネル＋上部の主要動作）を保てば、既に覚えた位置を活かせる（ヤコブの法則・位置の記憶）。処理の状態を上部バーに常設して見失いを防ぐ |
| B 工程ステッパー | `plan-b.html` | 1 画面に 1 工程の仕事だけを置き「戻る／次へ」で進めれば、次に何をするかを考えなくてよい（判断の数を減らす） |
| C 条件と結果の並置 | `plan-c.html` | 設定（① ② 条件 出力）の要約を常に結果の横に出せば、結果の理由を覚えておかなくてよい（記憶より再認） |
| D 処理の流れ | `plan-d.html` | 処理の流れの図を 1 本の帯にし、道案内・各段の状態・行数の根拠を兼ねれば、画面遷移と状態表示を 1 か所にまとめられる |
| E 表最大・文脈操作 | `plan-e.html` | 常に見える部品を最小にし表を最大にすれば、見るべき情報が増えない。設定は札の小窓・見出しのメニュー・機能検索から |

評価は `../design/02-レイアウト評価.md`。
